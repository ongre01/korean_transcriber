# Korean Transcriber 사용 및 구조 가이드

이 문서는 현재 저장소의 Qt GUI와 Python 엔진을 기준으로 작성한 사용·구조 안내서다. 실제 마이크, 모델, NPU 장치가 필요한 시나리오를 이 문서 작성 과정에서 실행해 검증한 것은 아니다. 실행 검증의 범위와 결과는 별도의 수용 검증 기록으로 관리한다.

## 1. 구성과 역할

Korean Transcriber는 Windows용 Qt Widgets 애플리케이션과 기존 Python 음성 인식 엔진을 분리한 구조다. GUI는 녹음, 파일 선택, 상태 표시, 결과 표시를 맡고, 음성 디코드·Whisper 전사·화자 분리는 Python이 수행한다.

```text
사용자
  │
  ├─ 기존 파일 선택 ──► AudioFileInfo ──► engine/audio_metadata.py
  │
  └─ 마이크 녹음 ────► AudioRecorder ──► WAV 파일
                                               │
                                               ▼
MainWindow ──► BackendProcess (QProcess) ──► engine/backend_bridge.py
                                               │
                                               ▼
                                    transcribe_npu.py / diarization.py
                                               │
                                  JSON Lines (stdout) / 진단 로그 (stderr)
                                               │
                                               ▼
                              MainWindow: 진행률·세그먼트·결과 표시
```

| 영역 | 주요 파일 | 책임 |
|---|---|---|
| GUI 시작 | `gui/main.cpp`, `gui/mainwindow.*` | 애플리케이션 초기화, UI 상태와 사용자 동작 관리 |
| 녹음 | `gui/audio/AudioRecorder.*`, `WavWriter.*` | 마이크 목록, 비동기 캡처, WAV 저장, 시간·레벨 전달 |
| 파일 검사 | `gui/input/AudioFileInfo.*`, `engine/audio_metadata.py` | 선택 파일의 존재·확장자·메타데이터 검사 |
| Backend 실행 | `gui/backend/BackendProcess.*` | Python 명령 실행, JSON Lines 검증, 취소·종료 처리 |
| AI 처리 | `engine/backend_bridge.py`, `transcribe_npu.py`, `diarization.py` | 전사·화자 분리 실행 및 GUI용 이벤트 생성 |
| 설정·로그 | `gui/settings/*`, `gui/logging/*` | `QSettings` 영속화, 애플리케이션 및 Backend 진단 로그 기록 |

`gui/AudioTranscriber.pro`는 `Qt Widgets`, `Qt Multimedia`, C++17을 사용한다. Qt 6에서는 `QAudioSource`, Qt 5 호환 경로에서는 `QAudioInput`을 사용하도록 분기되어 있다.

## 2. 사전 준비

### Python 엔진 준비

처음 실행하기 전에 `engine/setup.bat`를 실행한다. 이 스크립트는 다음을 수행한다.

1. `engine/.venv` 생성 또는 재사용
2. `engine/requirements.txt`의 런타임 패키지 설치·갱신
3. OpenVINO 사용 가능 장치 확인
4. INT8·FP16 Whisper 모델 준비
5. 화자 분리 모델 준비

`setup.bat`은 PATH에서 `python`을 찾아 가상 환경을 만든다. 완료 후 GUI 설정의 Python 경로에는 일반적으로 `engine/.venv/Scripts/python.exe`를 지정한다.

### GUI 빌드

Qt가 제공하는 명령 프롬프트에서 다음처럼 `gui` 프로젝트를 qmake로 생성·빌드한다. 사용하는 Qt Kit에 맞는 `qmake`와 빌드 도구를 사용해야 한다.

```bat
cd gui
qmake AudioTranscriber.pro
nmake
```

프로젝트의 기준 개발 환경은 Qt Widgets, qmake, C++17, Qt Multimedia다. `AudioTranscriber.pro`의 대상 이름은 `AudioTranscriber`다.

### 실행 위치와 엔진 탐색

GUI는 `engine/backend_bridge.py`와 기본 Whisper 모델을 현재 작업 폴더의 `engine/`에서 먼저 찾고, 실행 파일 폴더에서 상위 여섯 단계까지의 `engine/`도 탐색한다. 따라서 개발 중에는 저장소의 `gui/`와 `engine/` 디렉터리 관계를 유지하는 것이 안전하다.

## 3. 기본 사용 흐름

1. 애플리케이션을 실행하고 **설정**에서 Python 경로, Whisper 모델 폴더, 결과 출력 폴더를 확인한다.
2. 아래 두 방식 중 하나로 입력을 준비한다.
   - **기존 파일 선택**: 파일을 선택하면 Python 메타데이터 도구가 비동기로 파일을 검사하고, 성공 시 이름·경로·재생 시간·파일 크기를 표시한다.
   - **실시간 녹음**: 마이크를 선택하고 녹음을 시작한 뒤 중지한다. 정상적으로 마무리된 WAV가 자동으로 현재 입력 파일이 된다.
3. 실행 장치와 화자 분리 옵션을 지정한 뒤 **전사 시작**을 누른다.
4. 처리 상태, 진행률, 처리 시간과 전사 세그먼트를 확인한다.
5. 완료 후 결과를 저장하거나 결과 폴더를 연다. Bridge가 생성한 TXT와 SRT의 절대 경로가 완료 이벤트에 포함된다.

### 지원하는 기존 파일 형식

GUI의 초기 확장자 검사는 다음 목록을 허용한다. 실제 디코드 가능 여부는 Python 측 처리 결과에 따라 최종 판단된다.

```text
wav, mp3, m4a, aac, flac, ogg, mp4
```

### 녹음 파일

- 기본 녹음 폴더: `QStandardPaths::AppDataLocation/recordings/`
- 파일 이름: `recording_YYYYMMDD_HHMMSS.wav`
- 같은 초에 이름이 겹치면 `_001`, `_002`처럼 번호를 붙인다.
- 장치가 지원하면 mono 16-bit 형식을 우선 사용하며, 지원하지 않으면 장치의 기본 형식 중 WAV writer가 지원하는 형식을 사용한다.
- WAV 헤더를 마무리하고 파일 commit에 성공한 경우에만 녹음 완료 이벤트를 보낸다.

## 4. 전사 및 화자 분리

### 전사 옵션

GUI는 다음 장치를 제공한다.

| 옵션 | 동작 |
|---|---|
| `AUTO` | Bridge가 사용 가능한 장치 중 NPU, GPU, CPU 순으로 선택 |
| `NPU` / `GPU` / `CPU` | 지정 장치를 사용하며, 사용할 수 없으면 오류 |

기본 Whisper 모델 경로는 `engine/models/whisper-large-v3-turbo-int8`다. 전사를 시작하기 전에 GUI는 Python 실행 파일, Whisper 모델 폴더, 출력 폴더 및 시간 관련 설정값을 확인한다.

### 화자 분리

화자 분리를 켜면 화자 수를 `Auto`, `2`, `3`, `4`, `5` 중에서 선택할 수 있다. Bridge는 이를 기존 엔진의 diarization 인자로 변환한다. 기본 구성은 다음과 같다.

- speaker segmentation: NPU
- speaker embedding 및 clustering: CPU
- NPU segmentation을 사용할 수 없으면 기본적으로 CPU fallback

화자 번호는 Bridge와 GUI에서 1부터 시작한다. 화자 분리를 사용하지 않은 세그먼트의 화자 값은 비어 있을 수 있다.

## 5. UI 상태와 취소

애플리케이션은 다음 상태를 관리한다.

```text
Idle ── 파일 선택/녹음 완료 ──► InputReady ── 전사 시작 ──► Processing
 │                                  ▲                            │
 └──── 녹음 시작 ──► Recording ─────┘                            ├─ 성공 ► Completed
                                                                   └─ 실패 ► Error
```

| 상태 | 가능한 핵심 동작 |
|---|---|
| `Idle` | 녹음 시작, 파일 선택 |
| `Recording` | 녹음 중지 |
| `InputReady` | 녹음 시작, 파일 선택, 전사 시작 |
| `Processing` | 취소 |
| `Completed` / `Error` | 새 녹음 또는 파일 선택, 유효한 입력이면 재전사 |

취소 요청 시 `BackendProcess`는 먼저 Python 프로세스에 정상 종료를 요청한다. 기본 유예 시간 3초 안에 종료되지 않으면 프로세스를 강제 종료한다. 취소 뒤 입력 파일은 유지하고 상태는 `InputReady` 또는 `Idle`로 돌아간다.

## 6. GUI–Python 통신 계약

Qt와 Python의 정식 통신 계약은 [backend_protocol.md](../engine/backend_protocol.md)다. 핵심 규칙은 다음과 같다.

- Python Bridge의 stdout은 UTF-8 BOM 없는 JSON Lines 전용이다. 이벤트 하나는 한 줄의 JSON 객체이며 즉시 flush한다.
- 진단 로그, Traceback, 엔진의 사람이 읽는 출력은 stderr로 보낸다.
- Qt는 이벤트 형식과 순서를 검증한다. 빈 줄, JSON이 아닌 데이터, 알 수 없는 이벤트, 종료 이벤트 뒤의 데이터는 프로토콜 오류로 처리한다.
- 성공한 실행은 마지막에 `completed` 이벤트를 한 번 보내고 종료 코드 0으로 끝나야 한다. 실패한 실행은 마지막에 `error` 이벤트를 한 번 보내고 0이 아닌 코드로 끝나야 한다.

### 이벤트 종류

| 이벤트 | 핵심 필드 | 용도 |
|---|---|---|
| `state` | `value` | `preparing`, `loading_model`, `decoding_audio`, `transcribing`, `diarization`, `saving_result` 상태 표시 |
| `progress` | `value`, 선택적 처리 시간 | `0`~`100` 또는 진행률을 모를 때 `null` |
| `segment` | `start`, `end`, `speaker`, `text` | 화면에 전사 문장 추가 |
| `completed` | `text_file`, `srt_file` | 생성된 결과 파일의 절대 경로 전달 |
| `error` | `message` | 사용자용 간결한 오류 전달 |

Bridge 실행 인자와 각 값의 허용 범위는 계약 문서의 **Bridge 인자 계약**을 따른다. GUI는 명령 문자열을 shell로 조합하지 않고 `QProcess::setProgram()`과 `setArguments()`로 Python 실행 파일, 스크립트, 인자를 개별 전달한다.

## 7. 설정과 로그

설정은 `QSettings`의 `Settings` 그룹에 저장된다. 주요 항목은 다음과 같다.

- Python 실행 경로, 마지막 입력 폴더, 결과 출력 폴더
- 선택 마이크, 전사 장치, 화자 분리 사용 여부와 화자 수
- Whisper 모델 폴더, window/overlap 초, hotwords 파일, initial prompt 파일
- 화자 분리 모델 경로, clustering threshold, 최소 음성·무음 시간, diarization 장치와 CPU fallback 여부

기본 결과 폴더는 `QStandardPaths::DocumentsLocation/AudioTranscriber/`다. 기본 로그 폴더는 `QStandardPaths::AppDataLocation/logs/`다. 로그에는 애플리케이션 시작, 선택 마이크, 입력 파일, Python 명령, Backend 상태, 결과 파일, 오류 및 stderr 진단이 기록된다. GUI의 **도구 → 상세 로그 보기** 메뉴에서 로그 파일을 확인할 수 있다.

## 8. 오류를 확인하는 순서

1. **파일 선택 오류**: 파일 존재 여부와 지원 확장자를 확인한다. 그 다음 Python 메타데이터 도구의 stderr 진단을 확인한다.
2. **전사 시작 전 오류**: 설정에서 Python 실행 파일, Whisper 모델 폴더, 결과 폴더를 확인한다.
3. **전사 중 오류**: GUI의 사용자용 메시지를 확인하고, 상세 원인은 로그의 Backend stderr를 확인한다.
4. **NPU 문제**: 전사 장치를 `CPU` 또는 `GPU`로 바꾸거나, 화자 분리의 NPU fallback 설정을 확인한다.
5. **녹음 오류**: 마이크 연결·권한·선택 장치와 녹음 폴더 생성 권한을 확인한다.

## 9. 개발 시 지켜야 할 경계

- Qt/C++는 UI, 녹음, 상태, Python 프로세스 제어를 담당한다.
- Whisper, OpenVINO, 음성 디코드와 화자 분리 로직은 Python 엔진을 재사용한다.
- Streaming STT, 실시간 화자 분리, 재생·파형·타임라인·화자 이름 편집·회의 요약은 현재 1차 범위 밖이다.
- GUI와 Python 사이의 이벤트·인자 변경은 `engine/backend_protocol.md`와 C++의 `BackendEvent` 검증 로직을 함께 갱신해야 한다.
