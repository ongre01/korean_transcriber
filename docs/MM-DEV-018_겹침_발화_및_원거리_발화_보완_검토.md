## 2. 실험 방법

### 2.1 비교한 방식

모든 방식은 같은 Whisper 파이프라인과 같은 생성 설정을 쓰고, 제품과 같은 전사 경로(에너지 VAD로 음성 구간 검출 → 구간별 Whisper, `backend_bridge.transcribe_speech_regions`)를 거친다. 방식 간 차이는 전사하는 오디오와 전사 결과를 합치는 방법뿐이다.

| 방식 | 구현 | 전사 스트림 수 |
|---|---|---|
| `v1` (기준) | 변경하지 않은 V1 음성 분석·품질 점수·채널 선택·렌더링(`multimic`) 후 전사 | 1 |
| `single_<i>` | 장치 i 녹음만 전사 | 1 |
| `oracle_single` | 케이스마다 채점 후 오류가 가장 적은 `single_<i>`를 사후 선택. 실제로는 고를 수 없는 기준선 | - |
| `beamform_das` | 기준 장치 대비 GCC-PHAT 지연(±20 ms) 보정 후, 장치별 잡음 바닥 RMS의 역수 가중 합(noise-normalized delay-and-sum) | 1 |
| `merge_channels` | V1 전사를 기본으로 두고 모든 `single_<i>` 전사에서 중복이 아닌 세그먼트를 추가(채널별 STT 병합) | 1 + 장치 수 |
| `separation_<모델>` | V1 출력에 2화자 분리 모델을 적용하고 두 스트림을 각각 전사한 뒤 병합 | 2 |
| `v1_plus_separation_<모델>` | V1 전사를 기본으로 두고 분리 스트림 전사에서 중복이 아닌 세그먼트만 추가 | 3 |

**중복 판정(병합 공통):** 후보 세그먼트의 글자 중, 시간이 ±1초 안에 있는 기존 세그먼트 텍스트에 순서대로 들어 있는 비율(최장 공통 부분열 / 후보 글자 수)이 임계값 이상이면 중복으로 버린다. 본 실행의 임계값은 0.7이다. 실행 전 근거: 발화 풀에서 같은 깨끗한 발화를 두 장치로 전사한 결과가 최대 30% CER까지 달랐으므로 같은 발화의 재인식은 글자의 약 70% 이상을 공유한다고 보았고, 0.5로 두면 "네 좋습니다"처럼 흔한 어미("습니다")만 겹치는 새 발화가 중복으로 버려진다(단위 테스트로 고정). **실측(3.3절)은 이 근거를 뒷받침하지 않았다:** 0.5가 CER이 가장 낮았고 0.7은 누락을 조금 더 줄이는 대신 삽입이 약 2배였다. 이 방식은 누락 내용을 더하는 합집합이며, 단어 단위 투표(ROVER)는 하지 않는다.

**음원 분리 모델(사전 학습, 재학습 없음):** 두 모델 모두 ONNX 파일을 OpenVINO(엔진의 기존 의존성)로 CPU에서 실행했다.

| 이름 | 파일 / 크기 / SHA-256 | 원 모델 | 학습 데이터·라이선스(모델 카드 기재 사항) |
|---|---|---|---|
| `convtasnet` | `convtasnet_sepnoisy_16k.onnx` / 20,166,704 B / `3fa85c7b…a963fd` | [JorisCos/ConvTasNet_Libri2Mix_sepnoisy_16k](https://huggingface.co/JorisCos/ConvTasNet_Libri2Mix_sepnoisy_16k)의 ONNX 변환 [iamdgarcia/…-onnx](https://huggingface.co/iamdgarcia/ConvTasNet_Libri2Mix_sepnoisy_16k-onnx) (rev `da34e671`) | Libri2Mix(영어 낭독)+WHAM! 잡음. 원 모델 카드: WHAM! 잡음은 CC BY-NC 4.0(연구 전용), 모델은 CC BY-SA 3.0. 변환 저장소는 PyTorch 대비 SNR > 56 dB 일치를 주장 |
| `sepformer` | `sepformer_whamr16k.onnx` / 106,065,245 B / `d1e5ed49…b649553` | [speechbrain/sepformer-whamr16k](https://huggingface.co/speechbrain/sepformer-whamr16k)의 비공식 ONNX 변환 [tonythethompson/SepFormer-WhamR16k-ONNX](https://huggingface.co/tonythethompson/SepFormer-WhamR16k-ONNX) (rev `3f43d502`) | WHAMR!(영어, 잔향+잡음). Apache-2.0 표기. 변환 저장소는 원 모델과의 일치 검증을 공개하지 않음 |

두 파일의 SHA-256은 Hugging Face LFS 메타데이터와 일치함을 확인했다. 모델 파일은 `artifacts/mm-dev-018/models/`(저장소 제외 대상)에 두었다.

### 2.2 통제 케이스: 실제 녹음의 재조합

저장소에는 동시 발화·원거리 발화에 대한 사람 정답 전사가 없다(MM-DEV-017 1절). 또 샘플 녹음은 화자별 장치 간 음량 차이가 좁아(아래) 실제 "장치 A 근처 화자 / 장치 B 근처 화자" 배치가 없다. 그래서 실제 녹음에서 발화를 잘라 새 시간축에 배치하는 통제 케이스를 만들었다.

**샘플 녹음 특성(실측, `sample/recording_20261026_1.wav` = mic 1, `_2.m4a` = mic 2):**

| 항목 | mic 1 (wav) | mic 2 (m4a) |
|---|---:|---:|
| 잡음 바닥(100 ms 프레임 전력 10백분위) | −57.0 dBFS | −41.3 dBFS |
| 발화 세그먼트 수준 − 잡음 바닥(중앙값, 1,030개) | 30.1 dB | 17.2 dB |
| 세그먼트 수준 차 mic1 − mic2 (5/25/50/75/95 백분위) | −5.0 / −3.7 / −2.7 / −1.6 / −0.2 dB | |
| V1 선택 시간 비율(MM-DEV-017 multi) | 64% | 36% |

수준 차의 분포가 좁으므로(사분위 범위 2.1 dB) 두 장치는 모든 화자에게 비슷한 거리였다고 추정한다(의견). 따라서 거리 차이는 아래처럼 이득으로 모의했다.

**구성 절차** (`overlap_rnd/cases.py`, `experiment.py`):

1. V1 정렬(`plan_multi_audio_selection`)로 두 녹음을 기준 시간축에 맞춘다(입력 2 오프셋 87,229 샘플, −31.85 ppm; MM-DEV-017과 동일).
2. 장치마다 잡음 바닥 + 10 dB를 임계로 에너지 VAD를 하고, 모든 장치의 음성 구간을 합친다. 앞뒤 0.4초가 모든 장치에서 무음인 0.6~8초 구간을 후보로 한다.
3. 후보마다 기준 장치 발화 수준이 잡음 바닥보다 12 dB 이상인지 확인하고, 깨끗한(섞기 전) 구간을 장치별로 전사한다. 장치 간 전사 불일치가 CER 30% 이하인 발화만 풀에 넣는다. **정답 텍스트 = 기준 장치(mic 1)의 깨끗한 구간 Whisper 전사**이다(사람 전사가 아님).
4. 화자 임베딩(엔진의 `3dspeaker_speech_eres2net` 모델) 코사인 유사도 < 0.25인 쌍만 서로 다른 화자로 묶는다. 샘플의 화자 분리 라벨은 1시간에 수백 개로 과분할되어(예: "화자 776") 쓸 수 없었다.
5. 각 발화를 근처 장치 기준 활성 수준 −26 dBFS로 맞추고, 근처가 아닌 장치에는 `far_db`만큼 감쇠해 더한다. 각 쌍은 해당 분류의 모든 조건에 한 번씩 쓰인다(조건 간 대응 비교).

| 분류 | 조건 | 배치 |
|---|---|---|
| 동시 발화 `overlap` | `cross_6db_full`, `cross_12db_full` | 화자 A는 mic 1 근처, 화자 B는 mic 2 근처(반대 장치 −6/−12 dB). 짧은 쪽 발화 전체가 겹침 |
| | `cross_12db_half` | 같은 배치, 짧은 쪽 발화의 50%만 겹침 |
| | `colocated_full` | 두 화자 모두 두 장치에 원래 비율 그대로(샘플 녹음과 같은 상황). 전체 겹침 |
| 작은 원거리 발화 `far_small` | `tail_6db`, `tail_12db` | 긴 발화 L(≥3초, mic 2 근처) 끝 0.3초 전에 끝나는 짧은 발화 S(≤2초, mic 1 근처) |
| | `after_6db`, `after_12db` | S가 L 종료 0.4초 뒤 시작(겹침 없음, V1 최소 유지 시간·히스테리시스 영향 확인) |
| 대조군 `single` | `alone_near0_6db`, `alone_near1_6db` | 한 화자만, 겹침 없음. 방식별 부작용(중복 삽입, 분리 왜곡) 확인 |

### 2.3 지표

| 지표 | 정의 |
|---|---|
| CER (cpCER) | MM-DEV-017과 같은 정규화 후, 정답 발화들을 가능한 모든 순서로 이어 붙여 오류가 가장 적은 순서의 (S+D+I)/N. 두 화자를 적는 순서는 오류가 아니다 |
| 누락 발화 | 정답 글자 중 일치 비율(재현율) < 50%인 발화. MM-DEV-017 `missed-threshold`와 같은 기준 |
| 2차 발화 | 겹침의 두 번째 화자(B), 원거리 분류의 짧은 발화(S). 보완 대상 |
| 삽입률 | 삽입 글자 / 정답 글자. 병합의 중복 삽입·환각을 나타냄 |
| V1 대비 CER 차이 95% CI | 케이스를 복원 추출(2,000회, seed 20261027)한 대응 bootstrap |
| 비용 | 케이스 오디오 1초당 Whisper 시간·신호 처리 시간(CPU), 케이스당 전사 스트림 수 |

### 2.4 실회의 대리 분석(정답 없음)

MM-DEV-017 `20261026_baseline`의 V1 다중 입력 전사(1시간)를 기본으로 두고 `single_0`, `single_1` 전사를 기준 시간축으로 옮겨 같은 병합을 적용했다(`meeting-proxy`). 추가된 텍스트는 정확도 향상이 아니라 **회복 가능 내용의 상한**이다. 다음 두 원인을 분리한다.

- V1이 그 시간에 **같은 장치를 이미 선택**했다면 두 전사는 같은 오디오에서 나왔으므로 차이는 Whisper 디코딩 편차(창·문맥·VAD 차이)다.
- **다른 장치를 선택**했던 구간의 추가분만 채널 선택 손실일 수 있다. 장치별 V1 선택 시간으로 나눈 초당 추가 글자 수의 차이 × 해당 시간을 "초과분 추정"으로 쓴다. 디코딩 편차가 시간에 고르게 일어난다는 가정이 들어간 추정이다.

자모만으로 된 세그먼트(예: "ㅋㅋㅋ…")와 Whisper의 대표적 무음 환각 문구("감사합니다" 등 단독)는 어휘 추가분에서 따로 센다.

## 6. V1 비교와 도입 판단

### 6.1 방식별 판단 근거

- **빔포밍:** 장치 2대가 떨어져 있고 배열 형상을 모르면 지연합은 한 방향(주 화자)으로만 맞출 수 있고, 두 번째 화자를 분리하지 못한다. 측정에서도 CER 개선이 없었고 2차 화자 누락이 늘었다. 잡음 가중치를 다르게 주는 변형은 시험하지 않았다. 다만 동일 가중이면 두 화자를 평균할 뿐이라 구조적으로 같은 한계가 있다고 본다(의견).
- **음원 분리:** 두 사전 학습 모델 모두 겹침이 없는 단일 화자에서도 CER을 크게 악화시켰다(+49.6 / +69.9%p). 분리 스트림의 환각이 삽입으로 들어갔다. 이 크기는 정답 편향(8절)으로 설명되지 않는다. 시험한 모델은 영어 합성 혼합으로 학습됐고, ConvTasNet sepnoisy는 연구 전용 데이터 파생이라는 라이선스 제약도 있다.
- **채널별 STT 병합:** 이 티켓이 겨냥한 누락은 줄였다(겹침 28~41%, 원거리 44~50% 감소). 하지만 이득은 장치마다 다른 화자가 가까운 경우(`cross_*`)에 몰려 있고, 실제 샘플과 같은 배치(`colocated_full`)에서는 작았다(13 → 10/24). 대가는 Whisper 3.3배와 중복 삽입이다.

### 6.2 찬성 측 의견(도입 또는 PoC 진행)

- 사양서 13절의 핵심 한계(동시 발화·작은 원거리 발화 누락)를 병합이 실제로 줄였다. 임계값 0.5에서는 겹침·원거리 CER 악화 없이 2차 발화 누락이 19 → 14/48, 12 → 6/28로 줄었다.
- 새 의존성이 없다. Whisper·VAD·정렬 결과를 그대로 쓰므로 Python bridge 안에서 구현할 수 있고, C++/Qt 변경은 결과 표시 정도다.
- 실회의 대리 분석에서도 mic 2 쪽에 회복 가능한 내용이 V1 텍스트의 최대 3.6~8.2% 있다는 신호가 있다.
- 장치를 참석자 가까이 흩어 놓는 사용 방식이 늘면 이득이 커지는 구조다(`cross_*` 조건 결과).

### 6.3 반대 측 의견(도입 보류)

- 처리 시간이 Whisper 기준 3.3배다. MM-DEV-017 실측으로 V1 1시간 회의의 전사 단계가 2,059초(GPU 설정)였으므로 6,800초 안팎이 된다는 추정이 나온다. 사용성에 직접 영향을 준다.
- 회의 대부분은 겹침이 없다. 대조군에서 병합은 CER +1.2%p(0.5) ~ +10.7%p(0.7)이고 삽입이 늘었으므로, 회의 전체 CER로는 손해일 수 있다.
- 실회의에서 어휘 추가분의 45~47%는 같은 오디오의 디코딩 편차였고, 0.7 기준 추가분의 63%가 중복 여부를 텍스트로 가르기 어려운 구간이었다. 임계값도 같은 데이터에서 골랐다.
- 장치별 전사의 화자 라벨은 서로 대응하지 않으므로 화자 분리를 다시 설계해야 한다.
- 근거가 사람 정답이 아닌 Whisper 정답과 이득만 모의한 거리에서 나왔다. 이득 크기(분류별 누락 발화 7~16건 감소)는 이 한계에 민감하다.

### 6.4 추천 결론 (신뢰도: V1 미도입 80%, 병합 PoC 제안 70%)

1. **V1은 변경하지 않는다.** 사양서 13절의 한계 설명을 유지한다.
2. **빔포밍(장치 2대 분산 배치)과 현재 사전 학습 분리 모델은 기각한다.** 장치 하나가 다채널 배열 파일을 내는 경우(MM-DEV-017 9절 "다채널 파일")에만 빔포밍을 따로 검토한다.
3. **채널별 병합은 V2 후보로 "선택적 병합" PoC를 제안한다.** 전체 재전사 대신 V1이 버린 장치에도 음성이 검출된 구간(두 장치 동시 음성)에만 추가 전사를 적용해 비용을 줄인다. 중복 판정에는 텍스트 외에 Whisper 토큰 신뢰도와 시간 겹침을 쓴다.
4. **PoC 진입 조건(제안):** 5절 자체 녹음 세트(사람 정답, 겹침·원거리 이벤트 각 30개 이상) 준비.
   **성공 기준(제안):** 겹침·원거리 누락 30% 이상 감소, 겹침 없는 구간 CER 악화 1%p 이하, 전체 처리 시간 1.5배 이하.
5. **음원 분리 재검토 조건(제안):** 한국어 또는 실제 회의 잔향 데이터로 학습·검증된 모델이 OpenVINO에서 실행 가능할 때, 먼저 공개 회의 데이터(AliMeeting 등)와 이 실험의 대조군으로 거른다. 단일 화자 CER 악화 1%p 이하가 최소 조건이다.

## 8. 해석 제한

- **정답이 사람 전사가 아니다.** 깨끗한 구간의 Whisper(int8, beam 1) 전사이며, 채택 발화도 장치 간 최대 30% CER까지 달랐다. 수치는 "섞기 전 인식 내용을 얼마나 유지하는가"이고 절대 정확도가 아니다. 정답을 mic 1 전사로 만들었으므로 mic 1 쪽 결과에 유리한 편향이 있을 수 있다.
- **거리는 이득으로만 모의했다.** 원거리의 잔향 증가·지연은 반영하지 않았고, 두 클립을 더하면 배경 잡음도 더해진다. 실제 원거리 발화는 더 어렵다고 보는 것이 타당하다(의견).
- 한 회의실, 장치 2대, 한 회의에서 뽑은 발화다. 화자 임베딩으로 다른 화자를 골랐지만 같은 화자가 섞였을 가능성은 남는다.
- V1은 짧은 케이스마다 새로 실행되므로 긴 녹음에서의 이전 선택 상태(최소 유지 시간의 이월 등)는 반영되지 않는다.
- 실험은 CPU로 실행했다. 제품 기본 설정(GPU)과 Whisper 출력이 다를 수 있다.
- 실회의 대리 분석의 추가분은 청취 확인 전이다. 회복 내용의 상한이며 정확도 향상량이 아니다.
- 논문 수치(예: arXiv:2312.09746의 40.1% 상대 감소)는 이 실험의 측정값이 아니며 기대 성능으로 쓰지 않는다.
